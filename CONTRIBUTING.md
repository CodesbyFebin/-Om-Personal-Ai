# Contributing to OM

Thank you for helping build OM into a trustworthy, sovereign personal AI workspace.

## Before opening a change

1. Search existing issues and pull requests.
2. Keep the scope focused and explain the user problem.
3. Do not claim an integration is live without a real probe or test.
4. Never commit credentials, tokens, private endpoints or user data.

## Development

```bash
npm ci
npm run dev
npm run lint
npm test
```

## Pull requests

Include:

- what changed and why;
- screenshots for visible UI changes;
- tests or reproducible verification;
- security/privacy impact;
- whether a capability is implemented, configured, offline or planned.

Prefer small, reviewable commits. A maintainer may request changes before merge.

## Issues

Use a clear title, reproduction steps, expected/actual behavior and environment details. Remove secrets and personal information from logs.

## Conduct

Be respectful, evidence-driven and constructive. Harassment, spam and deceptive claims are not accepted.
